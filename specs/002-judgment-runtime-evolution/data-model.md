# Data Model: v0.2–v0.4 Judgment Runtime

本模型延续 [v0.1 数据模型](../001-judgment-foundation/data-model.md)。除可导出的脱敏观测报告外，所有实体均为内存中的执行状态；缓存没有持久化文件。判断核心不持有 DuckDB 向量、连接或凭据原文。

## 1. JudgmentIdentity（判断身份）

| 字段 | 规则 |
| --- | --- |
| `canonical_version`, `state_kind`, `canonical_bytes` | 完整规范化内容；文本与结构化状态区分，字段顺序规范化，类型及内部 NULL 保留 |
| `question_kind` | 二元或类别；`jev_prob` 与 `jev_bool` 使用同一二元请求语义 |
| `criterion` / `question`, `choices` | 原文和有序候选；不修剪，不按候选集合重排 |
| `provider_namespace`, `endpoint`, `requested_model` | 与一次调用的配置快照一致；不同服务或地址不能合并 |
| `effective_model` | 服务报告的实际模型，可能未知；跨查询复用需能在下次调用前验证稳定绑定 |
| `credential_scope` | 只在连接状态内用于隔离，不记录凭据原文或可反推的指纹 |

哈希只用于索引。相等关系必须比较完整身份；哈希碰撞不得产生相等判断。并发去重还需“进行中”状态，防止多个工作线程同时发送同一身份。跨查询缓存只在同一连接、同一凭据上下文、稳定模型身份下查询。

## 2. QueryExecution 与 RowTarget

`QueryExecution` 持有冻结的服务配置、优化开关、取消状态、连接内并发额度的引用和本次观测计数。每个有效输入构造 `RowTarget`：函数调用实例、数据块内行位置、问题类型及输出位置。同一 `JudgmentIdentity` 可以拥有多个 `RowTarget`。顶层 NULL 不产生身份或目标，直接输出 NULL；非法输入在提交前失败。

生命周期：`read → validated → deduplicated/cache-hit → queued → sent → response-validated → written`。任何阶段失败进入 `failed`，已发送请求计数保留，未校验结果不得写回。数据块外的行位置须带调用实例身份，不能只用局部索引。

## 3. BatchEnvelope 与 Answer

`BatchEnvelope` 由同一个能力已验证的服务、模型和凭据上下文中的多个不同判断组成。包括批次身份、每个判断的唯一关联键、行目标集合、容量/响应大小预算。只在服务支持的组合内合批；不支持时显式拒绝“合批模式”。

`Answer` 含关联键、问题类型、类型化值及服务报告的模型/用量/推理时间（若存在）。必须恰好覆盖批次中的全部关联键，无缺失、额外或重复；每个值沿用 v0.1 的概率范围与候选成员校验。批次解析完成后才能对结果回填或缓存。批次中任一项无效则整个查询失败。

## 4. ConnectionRuntime 与 CacheEntry

`ConnectionRuntime` 由宿主连接生命周期持有，不是进程全局共享缓存。它拥有有界缓存、跨该连接所有数据块的并发额度和观测窗口；连接关闭时释放。查询调用只取得共享引用，不自行创建跨连接可见的结果存储。

| CacheEntry 字段 | 规则 |
| --- | --- |
| 完整 `JudgmentIdentity` | 必须与访问请求逐项相等 |
| 已校验 `JudgmentResult` | 失败、部分或未校验结果不缓存 |
| 创建/到期时间 | 正的有效期；超过有效期不得命中 |
| 占用字节数 | 包含 key、值及管理开销的保守估计；条目数和字节双上限 |
| 模型绑定证据 | 可变别名不能预先验证仍绑定同一版本时禁止跨查询命中 |

状态：`miss → in-flight → validated → cached → hit | expired | evicted | cleared`。缓存默认关闭；显式启用后才能在不同查询间读写。配置或凭据作用域变化使旧条目不可命中，失败不进入 `cached`。缓存清空只作用于当前连接。并发额度使用自动释放机制，取消和错误时亦释放。

## 5. ProviderCapabilities

每个 adapter 声明并以真实证据验证：二元判断、类别判断、跨不同状态的合批、每批上限、响应身份规则、实际模型可得性、服务端推理时间和计费用量可得性。未验证的能力为 `unsupported`，不是猜测为支持。能力与协议版本关联；运行时先校验所需能力，再发请求。

v0.3 共享判断核心持有身份、校验、执行策略和抽象能力协议；具体服务负责请求/响应翻译；DuckDB 宿主负责配置、向量与连接生命周期。

## 6. ObservationWindow、MetricSample 与 CostEstimate

`ObservationWindow` 是连接中一次含判断的查询从 QueryBegin 到 QueryEnd 的观测区间，跨该查询相关判断函数调用聚合计数；连接只保留最近一次已结束查询的脱敏快照。它包含输入行、有效行、唯一判断、去重、缓存命中、外部请求、批次大小分布、失败数与总耗时。定义上 `unique_judgments` 是需判断的不同身份数，`external_requests` 是实际传输次数，两者不能互换。

`MetricSample` 区分客户端序列化耗时、客户端观测的完整外部往返耗时、服务报告的推理耗时和总耗时。外部往返包含传输和服务处理；各阶段可能嵌套，不能相加冒充总耗时。未报告的推理/纯网络耗时为 `unknown`，并注明来源。

`CostEstimate` 记录货币、单价及计费单位、用量、来源、估算时间和估值。任何必要值缺失则估值为 `unknown`。失败请求可能计费；估值不表示服务账单金额。可导出的报告只保留计数、时间、服务/模型标识及非敏感环境，不输出状态、问题原文或凭据。

## 7. ExperimentRun

一条实验记录固定数据集标识与行数、重复率、问题集合、服务/模型、环境版本、优化配置、预过滤条件、正确性、各计数和时间、费用估计及证据类型（真实服务/可控服务）。同一数据集分别运行逐行、预过滤、合批、缓存模式；1K、10K、100K 行各有完整四模式记录。真实服务能力未验证或计价缺失时，记录 `unsupported` / `unknown`，不可填入模拟测量。
