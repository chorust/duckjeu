## User Scenarios & Testing *(mandatory)*

### User Story 1 - 重复输入仍准确归位，减少重复判断 (Priority: P1；v0.2)

分析人员在同一批数据中反复遇到相同状态和问题，希望少付费、少等待，同时每一行仍收到属于自己的判断。启用优化后，重复内容可以共享一次有效判断；关闭优化时保持 v0.1 的逐行行为。

**Why this priority**: 去重和准确回填是批处理、缓存及成本控制的基础。

**Independent Test**: 用可控服务对包含重复、不同问题、NULL 和跨数据块边界的输入运行三种判断，比较优化开关前后的结果与实际外部请求数。

**Acceptance Scenarios**:

1. **Given** 同一执行中多行具有完全相同的规范化状态、问题类型和问题内容，**When** 启用去重，**Then** 只提交一次对应判断，每个原始行位置都得到该次经校验的结果；去重次数与外部请求数分别可见。
2. **Given** 状态相同但标准、问题、候选标签或顺序不同，**When** 启用去重，**Then** 它们仍被当成不同判断；两个状态只要类型或内部 NULL 不同，也不得合并。
3. **Given** 顶层 NULL、空数据集或非法输入，**When** 执行判断，**Then** 沿用 v0.1 的 NULL/错误规则；NULL 与空数据集不发起请求，非法输入不进入去重或缓存。
4. **Given** 服务把多个结果乱序返回，**When** 判断能逐项关联，**Then** 所有结果准确回填；缺失、重复、未知或无法唯一关联的结果使查询失败。

### User Story 2 - 有界地合批和并发执行 (Priority: P1；v0.2)

分析人员希望在大数据集上缩短等待时间，管理员希望服务请求量和同时运行的请求受控。系统按服务实际能力合并不同输入的请求，保持结果契约，并允许用户关闭优化进行逐行对照。

**Why this priority**: v0.2 的批处理必须对外部往返产生可核验的效果，不能只在内存中分组后继续逐行调用。

**Independent Test**: 对支持跨输入合批的可控服务运行至少两个不同有效状态，检查单次外部往返承载多个判断；再用真实兼容服务确认能力及结果。用并行查询检查连接内并发上限。

**Acceptance Scenarios**:

1. **Given** 服务已验证支持一次处理多个不同状态，**When** 启用合批处理这些状态，**Then** 外部请求数少于唯一判断数，响应逐项关联，结果与逐行对照在确定性样例中一致。
2. **Given** 服务不支持跨状态合批，**When** 请求启用合批，**Then** 明确报告该能力不可用；不得把仅有的内部分组或并发逐行请求称为合批完成。
3. **Given** 多个数据块和并行执行路径共享一个连接，**When** 设置并发上限，**Then** 该连接同时进行的外部请求不超过上限；失败或取消后等待中的工作可结束，不会无限占用额度。
4. **Given** 超时、部分响应或无效结果，**When** 一批判断失败，**Then** 查询报错，不输出未经校验的部分结果，不自动重试；已经发生的外部调用仍计入观测记录。

### User Story 3 - 明确控制缓存的成本和新鲜度 (Priority: P1；v0.2)

分析人员可选择短期复用已有判断，减少重复付费；管理员可限制占用和有效期。由于模型结果可能随时间变化，跨查询缓存由用户显式启用。

**Why this priority**: 缓存能降低费用，也会改变再次查询的结果新鲜度，因此必须可控、可解释。

**Independent Test**: 在一个连接中重复运行相同查询，检查启用前后命中、真实调用和淘汰；切换连接、服务、模型、问题或配置后验证隔离。

**Acceptance Scenarios**:

1. **Given** 未启用跨查询缓存，**When** 再次执行同一判断，**Then** 不复用前次查询的结果；同一次执行中的去重单独统计，不算缓存命中。
2. **Given** 显式启用缓存且请求上下文完全一致，**When** 在有效期内重复判断，**Then** 可以复用已校验结果；命中不产生外部请求，命中数与节省的请求数可核对。
3. **Given** 达到条目数或内存上限、有效期届满、相关配置变化，或模型别名无法被稳定绑定到具体版本，**When** 再次查询，**Then** 旧结果不被错误复用；淘汰和失效后可正常重新判断。
4. **Given** 另一连接、另一凭据上下文或一次失败判断，**When** 查询相同文本，**Then** 不读取前者的缓存，也不复用失败；缓存不持久保存敏感状态。

### User Story 4 - 在可信服务之间选择判断来源 (Priority: P2；v0.3)

分析人员可在现有远端 JEV 与经过验证的本地或自托管 JEV 兼容服务之间选择；维护者能复用相同的判断语义，而不依赖某个数据库或服务的协议。

**Why this priority**: 只有协议、模型和分数意义都得到验证，替换服务后结果才可正确解释。

**Independent Test**: 在不改变现有三种查询的条件下，分别调用远端和一个真实可访问的本地或自托管兼容服务，检查能力、模型身份、合法结果及不支持能力的错误。

**Acceptance Scenarios**:

1. **Given** 两个已验证的服务，**When** 用相同输入调用三个现有判断函数，**Then** 返回值类型、NULL、阈值、候选成员及失败规则一致；具体判断值无需相同。
2. **Given** 本地或自托管服务只支持部分问题类型或合批形式，**When** 调用不支持的能力，**Then** 在发起不适用请求前明确报错，且能力清单说明限制。
3. **Given** 请求模型是别名或服务未报告实际模型版本，**When** 查看验收或运行记录，**Then** 请求标识与实际标识分开记录，未知值明确标为未知；不得宣称不同模型或服务的概率可直接比较。
4. **Given** 服务切换或模型配置变化，**When** 再次执行相同判断，**Then** 不复用其他服务或模型的缓存；连接之间的配置不互相覆盖。

### User Story 5 - 看清时间、费用与优化收益 (Priority: P2；v0.4)

分析人员和维护者在固定数据集及环境中，了解序列化、外部等待、服务推理和总耗时，以及可核查的费用估计，再比较预过滤、合批和缓存的影响。

**Why this priority**: 没有可重复的观测和基线，就无法判断优化是否真正降低等待或费用。

**Independent Test**: 固定数据、问题、服务/模型、运行环境和计价假设，重复执行逐行、预过滤、合批、缓存模式，对比结果正确性、请求数、耗时和费用估计。

**Acceptance Scenarios**:

1. **Given** 一次有成功和失败调用的查询，**When** 查看执行概况，**Then** 可见行数、唯一判断数、外部请求数、缓存命中数、合批规模、总耗时及已能测得的阶段耗时；计数口径清楚，不能泄漏原始状态或凭据。
2. **Given** 服务提供可信的推理时间，**When** 展示阶段耗时，**Then** 推理时间注明为服务报告；若服务未提供，明确为未知，不从端到端等待中臆测网络或推理份额。
3. **Given** 有可核验的单价、计费单位和用量，**When** 估算费用，**Then** 显示计算依据和估算值；缺失任何必要依据时显示未知，且不把估算当成账单金额。
4. **Given** 固定的 1K、10K、100K 行数据，**When** 比较优化开关与预过滤，**Then** 每种模式有可复现的输入、环境、服务/模型、正确性、耗时、请求数、命中率和费用估计或未知原因；报告区分真实服务测量与可控服务测量。

### Edge Cases

- 跨数据块重复行、字段顺序不同但语义相同的结构化状态、哈希碰撞、文本与数值同形、内部 NULL 与字段缺失：合并前必须比较完整判断内容。
- 概率与布尔共享二元问题语义，但不同 SQL 调用并不自动保证同一次模型采样；缓存复用时须清楚说明。
- 一批请求或响应超出服务限制、超时、只返回部分结果、响应次序变化：拆分须保持身份关联，无法完整验证则报错；超时及响应大小限制仍有效。
- 并发请求跨多个数据块、同一连接多次查询、查询取消或线程故障：并发额度必须最终释放；已产生的外部费用不会随查询回滚。
- 模型别名被服务重新指向、服务未返回实际模型、缓存过期或配置变更：即使上一次响应曾报告实际模型，只要下一次不能确认别名仍绑定同一版本，就不得跨查询复用。
- 一批中有合法与非法输入，或合法与服务失败结果：不缓存失败，不将失败变为 NULL/0/false/空标签。
- 预过滤由查询执行器决定是否减少实际调用；报告只陈述实测请求数，不承诺过滤条件必然先于外部判断执行。
- 真实服务未提供批处理、推理耗时或计价数据：相应能力或指标标为不可用/未知，不能以模拟数据冒充真实验收。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001（v0.2）**: 优化模式 MUST 可显式启用和关闭；关闭时三种查询的逐行行为、NULL、错误及返回类型沿用 v0.1。启用后的结果仍须满足既有概率、布尔和标签契约。（故事 1–2）
- **FR-002（v0.2）**: 同次执行的去重 MUST 依据完整规范化状态及编码版本、问题类型、标准或问题原文、候选及顺序、服务身份、服务地址、请求模型与已知实际模型身份；哈希仅可用于定位，合并前必须比较完整内容。（故事 1.1–1.2）
- **FR-003（v0.2）**: 一个有效判断可关联多个原始行；批量或并发返回 MUST 逐项验证身份、数量、类型和值，再准确回填；无法关联、重复、遗漏或额外结果 MUST 使查询失败。（故事 1.1、1.4、2.4）
- **FR-004（v0.2）**: 合批能力 MUST 以目标服务实际支持的跨状态多判断请求为前提；启用时对至少两个不同有效判断减少外部往返。无法证明此能力的服务 MUST 明确标为不支持，不能宣称完成真实合批。（故事 2.1–2.2）
- **FR-005（v0.2）**: 用户 MUST 能限制单批判断数和连接内同时进行的外部请求数；限制适用于同一连接的所有数据块及并行查询，排队、失败和取消后不得永久占用额度。（故事 2.3）
- **FR-006（v0.2）**: 跨查询缓存 MUST 默认关闭、仅在用户显式启用后复用；用户 MUST 能设置正的条目数、内存和有效期上限，并能清空缓存。达到上限或过期 MUST 淘汰/失效，不得无界增长。（故事 3.1–3.3）
- **FR-007（v0.2）**: 缓存 MUST 只保存已完整校验的成功判断，在连接和凭据上下文之间隔离；服务、地址、模型、问题内容、规范化版本或相关配置变化 MUST 使旧结果不可命中。可变模型别名在下一次请求前不能确认仍绑定同一实际版本时 MUST 不跨查询复用，即使上次响应曾报告版本。（故事 3.2–3.4）
- **FR-008（v0.2）**: 去重、缓存和合批 MUST 分别报告独立计数；缓存不持久保存状态，错误、日志和观测输出 MUST 不包含凭据或原始敏感状态。（故事 1、3、5）
- **FR-009（v0.2）**: 必须在 1K、10K、100K 行固定样例上记录逐行对照与优化模式的结果正确性、耗时、外部请求数和缓存命中率；需包含重复率与唯一判断数，不能仅以返回行数估算请求数。（故事 2、5）
- **FR-010（v0.3）**: 现有远端服务和至少一个真实可访问、经过协议验证的本地或自托管 JEV 兼容服务 MUST 可选；二者沿用相同三函数公开契约。可控模拟服务不满足后者的真实验收。（故事 4.1）
- **FR-011（v0.3）**: 每个服务 MUST 公布经验证的问题类型、合批能力、实际模型标识可得性及概率/类别语义；不支持的能力 MUST 明确失败，不得以任意文本模型的自报数字冒充 JEV 概率。（故事 4.2–4.3）
- **FR-012（v0.3）**: 判断规范化、请求关联、结果校验及错误语义 MUST 成为不依赖特定数据库或服务协议的共享核心；服务切换 MUST 不改变现有 SQL 契约，连接配置保持隔离。（故事 4.1、4.4）
- **FR-013（v0.3）**: 运行与验收记录 MUST 区分服务、请求模型、服务报告的实际模型及未知状态；不同服务或模型的分数 MUST 不被默认视为可比较或已校准。（故事 4.3）
- **FR-014（v0.4）**: 执行概况 MUST 记录输入/有效/唯一判断数、合批数及规模、实际外部请求数、缓存命中数、失败数、总耗时和可测阶段耗时；指标定义 MUST 避免重复计数。（故事 5.1）
- **FR-015（v0.4）**: MUST 区分客户端序列化时间、客户端观测的外部往返时间与服务报告的推理时间；没有服务报告时网络/推理拆分 MUST 标为未知，不得用估算冒充实测。（故事 5.2）
- **FR-016（v0.4）**: 费用 MUST 按可核查的单价、计费单位、实际用量和估算时间计算并标明来源；缺少依据 MUST 显示未知，失败请求的可能计费 MUST 不被静默排除。（故事 5.3）
- **FR-017（v0.4）**: 评估 MUST 使用固定数据、问题、服务/模型、配置和环境，对预过滤、合批、缓存分别与逐行基线比较；同时记录正确性与观测指标，并标明真实服务和可控服务的证据边界。（故事 5.4）
- **FR-018（全阶段）**: v0.1 的顶层 NULL、非法输入、超时、响应大小、脱敏、明确报错及不自动重试规则 MUST 保持；查询失败不能宣称撤销外部调用与费用。（故事 1–5）
- **FR-019（范围）**: v0.2 交付执行策略与缓存，v0.3 交付共享判断核心与经验证的第二类服务，v0.4 交付观测与对照报告；PostgreSQL、集合 judgment、JDL、持久化判断存储及自动业务策略属于后续里程碑。（全部故事）

### Key Entities

- **判断身份**：完整规范化状态、问题类型及内容、候选顺序、编码版本、服务与模型上下文；决定两次判断是否可安全合并或复用。
- **行关联**：一个有效判断对应的原始输入行位置集合，以及请求和响应的身份；用于乱序结果回填。
- **执行策略**：用户选择的优化开关、批量大小、并发上限和失败行为；在一次执行中保持一致。
- **缓存条目**：判断身份、经校验的结果、创建及失效时间、占用大小；只在允许的连接/凭据上下文中有效。
- **服务能力与模型记录**：服务支持的问题类型和合批形式、请求模型、实际模型及其可得性、概率和类别语义证据。
- **执行概况**：各阶段计数与耗时、费用估算依据、未知指标原因；不包含原始敏感状态或凭据。
- **对照实验**：固定数据与环境、模式、正确性、耗时、请求数、命中率、费用估算和证据来源。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001（v0.2）**: 固定确定性样例中，三种结果形式在优化模式下与逐行基线的合法性及行归属一致率为 100%；包含跨数据块重复行、乱序响应及全部既有 NULL/错误场景。
- **SC-002（v0.2）**: 对有重复判断的样例，启用去重后的实际判断数等于唯一判断数；对至少两个不同判断，已验证支持合批的服务的外部往返数少于唯一判断数；测得的连接内峰值并发不超过设置值。
- **SC-003（v0.2）**: 缓存容量与有效期限制在所有边界样例中 100% 生效；跨连接、跨凭据、跨服务/模型、失败结果的错误命中为零；报告 1K、10K、100K 行的耗时、请求数和命中率三组结果。
- **SC-004（v0.3）**: 现有远端服务及至少一个真实本地或自托管兼容服务，均完成三种判断形式各至少三行非敏感输入的验收；类型、值域、行映射和错误契约符合率为 100%，并记录实际模型或未知。
- **SC-005（v0.4）**: 固定 1K、10K、100K 行数据在逐行、预过滤、合批、缓存四种模式下均有可复核记录；每条记录包含输入与环境、正确性、实际请求数、命中率、总耗时和费用估算或未知原因。
- **SC-006（v0.4）**: 观测报告中凭据与原始敏感状态泄漏数为零；推理时间和费用缺乏依据时错误标注为实测或已计费金额的次数为零。

## Assumptions

- 本次一个 feature 覆盖 roadmap 的三个连续里程碑，但各版独立验收与标记状态；完成规格不等于完成实现。先完成 v0.2，随后 v0.3、v0.4。
- v0.1 的三函数、规范化状态和失败契约继续有效；优化开关关闭时保留逐行行为。缓存可能使结果不再新鲜，因此跨查询复用默认关闭。
- 服务能否真正跨状态合批、是否报告推理时间或实际模型，需要规划和真实集成时验证；缺失能力不能用可控模拟代替真实证据。
- TypeSafe 已核实为单一顶层 state 与多个 question key；把不同输入行组成一个 state 的合批方式会让各问题看到共享上下文，因此需真实服务验证、显式启用并向用户说明可能的结果差异，不能把它称为原生独立状态批量接口。
- 本地或自托管服务须实际可访问且其 JEV 兼容能力经过验证；本地部署方式和具体协议在规划阶段确认。
- 缓存限制针对单连接及其相关执行；不同连接的总体服务并发与内存占用可另行配置或监控，不假设单连接上限就是全进程上限。
- 费用估算依赖服务计价与用量数据；不承诺费用下降的固定比例或推理耗时的固定改善。实验仅报告所测环境的结果。
- 项目 constitution 仍为未填写模板；本规格依据用户指令、roadmap、根规格与已验收的 v0.1 契约。
